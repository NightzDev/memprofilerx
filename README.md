# 🧠 MemProfilerX

**Professional Python memory profiler** — Track, visualize, and analyze memory usage in real time with production-grade tools.

Modern, type-safe, and developer-friendly. From quick debugging to production monitoring.

---

## ✨ What's New in v0.3.0

### 🕵️ Leak Hunter — find the exact line that leaks

```python
from memprofilerx import find_leaks

report = find_leaks(handle_request, payload, iterations=50)
print(report)
```

```
MemProfilerX leak report: 50 iterations (after 3 warm-up), traced memory +91.2 KB (+1.8 KB/iteration)
  ✘ 1 leak suspect(s):
  1. app/sessions.py:42  +91.2 KB total, +1.8 KB/iter, +200 objects, grew in 100% of iterations
       → _sessions[user_id] = {"user": user, "payload": payload}
```

It runs your code repeatedly, diffs `tracemalloc` snapshots and only reports lines that grow
**consistently** — warm-up caches and one-off allocations are ignored. Works with sync and
`async` functions.

From the terminal (exit code `1` on leaks — drop it in CI):

```bash
memx leaks app/handlers.py:handle_request -n 50
memx leaks mypkg.jobs:process --json
```

For loops you already have:

```python
from memprofilerx import LeakDetector

with LeakDetector(raise_on_leak=True) as det:
    for msg in messages:
        consume(msg)
        det.checkpoint()
```

### 🧪 Pytest plugin — stop memory regressions in CI

Installed automatically. No config needed.

```python
import pytest

@pytest.mark.no_leaks(iterations=30, threshold="10 KB")
def test_handler_does_not_leak(client):
    client.get("/orders/1")          # body runs 30x; fails pointing to the leaking line

@pytest.mark.memory_limit("50 MB")
def test_import_csv():
    import_big_csv("fixtures/big.csv")  # fails if Python allocations peak above 50 MB

def test_service(memx_leaks):
    memx_leaks(service.process, payload, iterations=50)
```

### 🌐 Universal web middleware — which endpoint is eating my memory?

One middleware, **every Python web framework**: anything ASGI (FastAPI, Starlette, Litestar,
Quart, Django ASGI, BlackSheep…) or WSGI (Flask, Django, Bottle, Falcon, Pyramid…).

```python
# FastAPI / Starlette / Litestar
from memprofilerx import MemoryMiddleware
app.add_middleware(MemoryMiddleware, stats_path="/__memx__", alert_threshold="50 MB")

# Flask
from memprofilerx import WSGIMemoryMiddleware
app.wsgi_app = WSGIMemoryMiddleware(app.wsgi_app, stats_path="/__memx__")

# Django (asgi.py / wsgi.py)
application = MemoryMiddleware(get_asgi_application())
application = WSGIMemoryMiddleware(get_wsgi_application())
```

* Per-route stats (`/users/42` and `/users/7` are grouped as `/users/{id}`)
* `GET /__memx__` → JSON with retained memory per route and **leak suspects**
* `alert_threshold` + `on_alert` callback for requests that blow up RSS (send to Sentry/Slack/logs)
* `add_headers=True` → `X-MemX-RSS-MB` / `X-MemX-Delta-MB` response headers
* `exclude_paths=["/health", "/static"]`, custom `path_normalizer`, `on_request` hook
* `middleware.stats.report()` prints a readable table

> ⚠️ Don't expose `stats_path` publicly — leave it `None` or protect it.
> RSS is process-wide: under heavy concurrency single-request deltas overlap, but
> per-route retained growth over many requests remains a reliable leak signal.

## ⚙️ Usage

### Quick Start: Decorator API

```python
from memprofilerx import track_memory

@track_memory(interval=0.5, analyze_gc=True)
def process_data():
    data = [i * 2 for i in range(10_000_000)]
    return sum(data)

result = process_data()
print(f"Result: {result['result']}")
print(f"Peak memory: {max(m for _, m in result['memory_usage']):.2f} MB")
print(f"Live objects: {result['live_objects']}")
```

---

### Global Process Tracking

Monitor your entire application with all export formats:

```python
from memprofilerx import global_tracker

@global_tracker(
    interval=0.5,
    export_png="memory.png",      # Visualization
    export_html="report.html",     # Interactive report (via JSON + convert)
    export_csv="memory.csv",       # Spreadsheet data
    export_json="memory.json"      # Raw data
)
def main():
    # Your application code
    data = [i for i in range(10_000_000)]
    process(data)

main()
```

---

### CLI: Profile Any Script

No code modifications needed - just use the CLI:

```bash
# Basic profiling with PNG output
memx run my_script.py

# Custom interval and HTML report
memx run my_script.py --interval 0.5 --format html --output report

# Export all formats at once
memx run my_script.py --format all --output analysis

# Convert existing JSON to other formats
memx convert memory.json --format html --output report.html
```

---

### Interactive HTML Reports

Generate beautiful, interactive reports:

```python
from memprofilerx import global_tracker
from memprofilerx.reporter import export_to_html
import json

# Track with JSON export
@global_tracker(interval=0.3, export_json="memory.json")
def data_pipeline():
    # Your code here
    pass

data_pipeline()

# Convert to interactive HTML
with open("memory.json") as f:
    data = json.load(f)
export_to_html(data, "report.html")
```

The HTML report includes:
- 📊 Interactive Plotly charts
- 📈 Statistics (peak, average, min memory)
- 📋 Detailed timeline table with deltas
- 🎨 Beautiful dark theme UI

### Real-time Monitoring with Callbacks

React to memory changes as they happen:

```python
from memprofilerx import track_memory
import logging

def alert_on_high_memory(timestamp: float, memory: float) -> None:
    if memory > 500:  # 500 MB threshold
        logging.warning(f"⚠️ High memory: {memory:.2f} MB at {timestamp:.1f}s")
        # Send alert, trigger GC, etc.

@track_memory(interval=1.0, callback=alert_on_high_memory)
def long_running_task():
    # Your code
    pass
```

## 🛠️ Development

### Setup Development Environment

```bash
# Clone repository
git clone https://github.com/NightzDev/memprofilerx.git
cd memprofilerx

# Install Poetry (if not already installed)
curl -sSL https://install.python-poetry.org | python3 -

# Install dependencies
poetry install --with dev,docs

# Install pre-commit hooks
poetry run pre-commit install
```

### Run Tests

```bash
# Run all tests
poetry run pytest

# Run with coverage
poetry run pytest --cov

# Run specific test file
poetry run pytest tests/test_tracker.py

# Run with verbose output
poetry run pytest -v
```

### Code Quality

```bash
# Format code
poetry run black src tests
poetry run ruff format src tests

# Lint code
poetry run ruff check src tests

# Type check
poetry run mypy src

# Run all checks (what CI runs)
poetry run pre-commit run --all-files
```

### Build Documentation

```bash
# Serve docs locally
poetry run mkdocs serve

# Build docs
poetry run mkdocs build
```

### Release Process

1. Update version in `pyproject.toml`
2. Update `CHANGELOG.md`
3. Create git tag: `git tag v0.2.0`
4. Push tag: `git push origin v0.2.0`
5. GitHub Actions will automatically publish to PyPI
